# 아키텍처 설명서 생성 (nova-architecture)

도메인/시스템의 구조를 문서화한다. 목적은 **AI가 다음 작업에서 "이 시스템이 어떻게 동작하는지"를 빠르게 복원**하는 것. 새 팀원/새 세션이 이 문서만 읽고 맥락을 잡을 수 있어야 한다.

## 출력 위치

`docs/architecture/<도메인>.md` (REPO_ROOT 기준 — Nova 자산 sync 대상).

## 절차

1. 진입점(라우터/컨트롤러) → 서비스 → 데이터 접근 → 외부 의존을 따라가며 실제 흐름을 코드에서 확인한다.
2. 아래 섹션을 채운다. 다이어그램은 Mermaid를 우선 사용(없으면 ASCII).

## 필수 섹션

### 1) 전체 흐름 (Big Picture)
시스템 구성요소와 데이터 흐름을 한 장으로. Mermaid `flowchart` 또는 ASCII.

### 2) 시퀀스 다이어그램
핵심 유스케이스 1~3개를 Mermaid `sequenceDiagram`으로(클라이언트→라우터→서비스→저장소→외부).

### 3) Entity 관계도
주요 도메인 엔티티와 관계. Mermaid `erDiagram` 또는 표. (상세 DB 스키마는 `nova-db-erd` skill 참조 링크.)

### 4) 계층별 책임
도메인모델(자기 상태)/비즈니스(오케스트레이션)/쿼리·필터/데이터 접근으로 구분해 어떤 파일이 어느 계층인지 매핑.

### 5) 테스트 시나리오
정상/엣지/실패 경로를 표로(시나리오 | 입력 | 기대 결과).

### 6) 권한 구분 (해당 시)
역할별 접근 가능 동작.

## 규칙

- 코드 근거를 `파일:라인`으로 표기해 신뢰도를 높인다.
- "현재 상태(as-is)"를 적되, 알려진 한계/TODO는 별도 표기.
- 완료 후 한 줄 요약 + 관련 문서(기능명세서/ERD) 링크.

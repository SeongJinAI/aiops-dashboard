# 바이브코딩 산출물 정의 (Vibe-Coding Artifacts)

> AI 코딩 어시스턴트(Claude Code 등)로 개발을 진행할 때 **생성되는 모든 산출물**을 정의한다.
> 코드 근거 기반(파일·Hook 스크립트·DB 카테고리 실측). Nova의 수집(Track)·자산화(Wikify)·코칭(Coach) 대상의 단일 진실의 원천.
>
> 작성: 2026-06-01 · 근거: `server/scripts/hooks/*.sh`, `server/services/*`, `server/routers/*`, 실 DB(tenant edf0aee3) 카테고리 실측

---

## 0. 5계층 분류 + 생명주기

바이브코딩 산출물은 **생성 방식·수명·용도**에 따라 5계층으로 나눈다.

| 계층 | 정의 | 생성 주체 | 수명 | Nova 단계 |
|------|------|----------|------|-----------|
| **1. 활동 산출물** | 작업 중 자동으로 흘러나오는 흔적(프롬프트·도구호출·세션) | 자동(도구 Hook) | 휘발 → 수집 시 누적 | **Track** |
| **2. 컨텍스트 산출물** | AI의 행동을 규정하는 설정·규칙 | 수동(개발자) | 누적·영구 | Track(스냅샷) |
| **3. 지식 산출물** | 의도적으로 작성하는 문서(명세·아키텍처·매뉴얼) | 수동(개발자) + 자동(위키) | 영구 | **Wikify** |
| **4. 코드 산출물** | 실제 결과물(소스·테스트·API·DB·UI) | 수동(개발자) | 영구 | — |
| **5. 코칭 산출물** | 1~4를 분석해 파생 생성되는 인사이트 | 자동(Nova) | 갱신 | **Coach** |

```
[작업]  → 1.활동 ─┐
[설정]  → 2.컨텍스트 ┤→ (Track 수집) → (Wikify 자산화) → (Coach 코칭) → 5.코칭 산출물
[문서]  → 3.지식 ──┤
[구현]  → 4.코드 ──┘
```

핵심 원칙: **흩어지면 휘발, 수집되면 자산.** 1·2계층은 가만두면 사라지고, 수집해야 3·4·5계층의 재료가 된다.

## 1. 활동 산출물 (Activity) — 자동 생성, Track 대상

작업 중 도구 Hook이 자동으로 기록한다. **로컬 `.aiops/{카테고리}/{YYYY-MM-DD}.jsonl` → 원격 `/api/ingest` → SQLite `logs(tenant_id, category, ts, payload)`**.

### 1-1. 생성 원천 — Hook 이벤트

| Hook 이벤트 | 발동 시점 | 캡처 | Nova 수집 |
|------------|----------|------|----------|
| `UserPromptSubmit` | 프롬프트 제출 | 프롬프트·토큰·슬래시명령 | ✅ `aiops-log-prompt.sh` |
| `PostToolUse` | 도구 호출 후 | 도구명·exit·소요시간·파일경로 | ✅ `aiops-log-hook.sh` |
| `SessionStart` / `Stop` | 세션 시작/종료 | 세션 경계 | ✅ `aiops-log-event.sh` |
| `PreCompact` | 컨텍스트 압축 전 | 압축 트리거 | ✅ `aiops-log-event.sh` |
| `SubagentStop` | 서브에이전트 종료 | subagent_type·토큰 usage | ✅ `aiops-log-event.sh` |
| `PreToolUse` | 도구 호출 전 | (차단 판정용) | ⬜ 미수집(거버넌스 전용) |
| `Notification` | 알림/푸시 | 알림 메시지 | ⬜ 미수집 |

### 1-2. 수집되는 카테고리 (실 DB 기준 10종)

| 카테고리 | 주요 필드 | 원천 | 비고 |
|---------|----------|------|------|
| **prompts** | `ts, prompt(앞 200자), repo, tokens, session_id, slash_command?` | UserPromptSubmit | AI에게 보낸 모든 지시 |
| **tool-use** | `ts, tool_name, file_path?, exit, ms, repo, session_id` | PostToolUse | 개별 도구 호출(Read/Edit/Write/Bash/Grep…) |
| **hooks** | `ts, hook, tool_name, script, exit(0/2), ms, repo, is_mcp, is_md_edit` | PostToolUse | Hook 실행 기록(거버넌스 통과/차단) |
| **mcp_calls** | `ts, tool_name(mcp__*), exit, ms, is_mcp=true` | PostToolUse 필터 | MCP 도구 호출(Notion/Drive/Gmail…) |
| **slash_commands** | `ts, slash_command, prompt, tokens, session_id` | UserPromptSubmit 파싱 | `/clear`·`/config`·Skill 호출 |
| **sessions** | `ts, event(SessionStart\|Stop\|PreCompact), session_id, trigger?` | 세션 Hook | 세션 경계 + 압축 |
| **agents** | `ts, event(SubagentStop), subagent_type, usage(토큰), session_id` | SubagentStop | 서브에이전트 실행 |
| **misunderstandings** | `ts, prompt, prev_prompt, pattern(rejection\|correction\|retry), keywords[]` | **자동 파생** | prompts/hooks 분석 후 감지 |
| **claude-config-global** | `.claude` 전역 설정 스냅샷 | install/sync | 컨텍스트 스냅샷(2계층 연동) |
| **claude-config-project** | 프로젝트 `.claude` 설정 스냅샷 | install/sync | 컨텍스트 스냅샷(2계층 연동) |
| *(workflow)* | `ts, workflow, step, stepNum, total, repo` | — | ⚠️ 형식만 정의, **수집 Hook 미구현** |

> 공통 필드: `ts`(ISO8601 KST), `repo`(저장소명), `session_id`(Claude Code 세션). `misunderstandings`는 수집이 아니라 **prompts/hooks에서 규칙 기반으로 파생**되는 유일한 활동 산출물.

### 1-3. 아직 산출물화 안 된 활동 (잠재 — 확장 후보)

도구는 생성하지만 Nova가 아직 카테고리화하지 않는 것: **PreToolUse 차단 상세, Notification, Worktree 진입/퇴출, CWD 변경, 토큰/비용 정밀 회계.** (현재는 `agents.usage`로 일부만)

## 2. 컨텍스트 산출물 (Context) — AI 행동을 규정하는 설정

개발자가 작성하며, AI의 모든 활동에 영향을 준다. 누적·영구. Nova는 스냅샷(`claude-config-*`)으로 일부 추적.

| 산출물 | 위치 | 구성 |
|--------|------|------|
| **CLAUDE.md** | 루트 / `~/.claude/` | 프로젝트·전역 지침(개요·스택·규칙) |
| **.claude/rules/** | `.claude/rules/*.md` | 도메인 규칙(백엔드·프론트·예외처리·코드리뷰·워크플로) |
| **.claude/agents/** | `.claude/agents/*` | 커스텀 서브에이전트 정의 |
| **.claude/skills/** | `.claude/skills/*` | 슬래시 명령(Skill) 정의 |
| **settings.json** | `.claude/settings(.local).json` | permissions allowlist · Hook 매처 · 플러그인 |
| **~/.claude/.env** | 사용자 홈 | `AIOPS_REMOTE_URL`·`API_KEY`·`TENANT_ID`, BYOK LLM 키 |
| **MCP 설정** | `.mcp.json` 등 | 연결된 MCP 서버 |

## 3. 지식 산출물 (Knowledge) — 의도적 문서

가장 가치가 큰 자산. **개발 워크플로 필수 산출물(아래 ★)** + 세션 기록 + 위키(Wikify가 자동 생성).

### 3-1. 개발 워크플로 필수 산출물 (★ = 기능 개발 완료 시 반드시)

> 개발 순서: **문서 → 코드 → 매뉴얼** (`개발워크플로_원칙`)

| 산출물 | 필수 내용 | 단계 |
|--------|----------|------|
| ★ **기능명세서** | API 명세(Method/URL/요청·응답), 검증 흐름도(ASCII), 검증 체크리스트(조건/에러코드) | 코드 전 |
| ★ **아키텍처 설명서** | Big Picture, 시퀀스 다이어그램, Entity 관계도, 테스트 시나리오, 권한 구분 | 코드 전 |
| ★ **사용자 매뉴얼** | 최종 사용자 관점 사용법 | 코드 후 |
| ★ **에러 메시지 문서** | 신규 `ERR_*` 코드(중앙 관리) | 코드 후 |

### 3-2. 운영·기획 문서

| 산출물 | 설명 | 생성 |
|--------|------|------|
| **HANDOFF.md** | 시점별 인수인계(완료/다음작업/주의/파일). `/clear` 시 필수 갱신 | 수동 |
| **프로젝트 기획서** | 비전·미션·타겟·핵심가치·백로그 | 수동 |
| **구현 가이드** | 기술 명세·API·데이터 형식·컴포넌트 분리 | 수동 |
| **인사이트/트러블슈팅 노트** | 재사용 가능한 깨달음 | 수동 |
| **발표 자료** | 프로젝트 소개 덱 + 데모 스크립트 | 수동 |

### 3-3. Wikify 자동 생성 (Nova) — 흩어진 .md → 구조화 위키

| 산출물 | 내용 | 근거 |
|--------|------|------|
| **프로젝트 위키 (3-perspective)** | `.md` 자산을 **기획자/개발자/사용자** 관점 챕터로 LLM 재구성(버전 관리) | `services/hermes/wiki_builder.py` |
| **자산 카탈로그** | 프로젝트 `.md`를 perspective·bucket으로 자동 분류 | `services/hermes/catalog.py` |
| **위키 diff 요약** | 이전↔신규 챕터 변화(헤딩 추가/제거·글자수·한 줄 요약) | `services/hermes/diff.py` |

## 5. 코칭 산출물 (Coaching) — Nova가 파생 생성 (Coach)

1~4계층을 분석해 자동 생성. **이 프로젝트의 차별 가치.**

| 산출물 | 구성 | 근거 |
|--------|------|------|
| **협업 점수 리포트** | 점수 3종(명확성/거버넌스/꾸준함) + 인사이트 6종 + 헤드라인 (룰 기반, LLM 불필요) | `services/coach.py` |
| **코치 브리핑** | 인사이트를 BYOK LLM이 한국어 1~8문장 요약 | `services/coach.py:synthesize` |
| **프롬프트 라이브러리 템플릿** | opt-in 프롬프트를 **주제별 익명 템플릿**으로 증류(원본 비공개) | `services/prompt_library.py` |
| **오해 패턴 리포트** | rejection/correction/retry 패턴 분포 | `services/misunderstanding_detector.py` |

## 6. 한눈에 — 산출물 × 단계 × 주체

| 계층 | 대표 산출물 | 생성 | Nova 단계 | 구현 |
|------|------------|------|-----------|------|
| 1 활동 | prompts·tool-use·hooks·sessions·agents·mcp_calls·slash·misunderstandings | 자동 | **Track** | ✅ |
| 2 컨텍스트 | CLAUDE.md·rules·settings·.env | 수동 | Track(스냅샷) | 🟡 부분 |
| 3 지식 | 기능명세·아키텍처·매뉴얼·에러문서·HANDOFF + **위키** | 수동 + **자동 위키** | **Wikify** | ✅ |
| 4 코드 | 소스·테스트·API·DB·UI | 수동 | — | ✅ |
| 5 코칭 | 협업점수·브리핑·템플릿·오해리포트 | **자동(Nova)** | **Coach** | ✅ |

> **요약:** 바이브코딩은 가만두면 1·2계층이 휘발한다. Nova는 이를 **수집(Track)**해 **위키로 자산화(Wikify)**하고, 다시 **코칭 산출물(Coach)**로 환원해 개인을 끌어올린다.
